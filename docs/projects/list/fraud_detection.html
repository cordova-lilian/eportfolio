Overview

Fraud detection is one of the most pressing challenges facing the banking sector today. Financial institutions must balance the operational cost of reviewing transactions against the financial and reputational cost of missing fraudulent ones. This project was developed as part of the Statistical Models and Methods for Business Analytics module, and applies the statistical techniques covered in class to a real-sized transaction dataset.

NoteWhat this project covers
  1. Descriptive statistics and outlier detection using IQR and Z-scores
  2. Correlation analysis between demographic, financial, and behavioural variables
  3. Exploratory segmentation by age, gender, education, and marital status
  4. Classification modelling with Decision Trees and Random Forest
  5. Honest reflection on model limitations and what the data can — and cannot — tell us

The Dataset

The dataset consists of 500 transactions and 23 original variables including demographic features (age, gender, education, marital status, region), financial features (personal and family income, credit score, loan amount), and behavioural features (transaction amount, device type, mobile and internet usage). The two key target variables are is_fraud (binary indicator) and fraud_amount (total monetary loss).

Outlier Detection

Outliers are particularly relevant in fraud detection, since fraudulent transactions often appear as extreme values in one or more dimensions. I used two complementary approaches: Z-scores and the IQR method.

Z-Score analysis

Show the code 
df_fraud = df[df['is_fraud'] == 1].copy()
numeric_cols = ['age', 'personal_income', 'family_income', 'credit_score',
                'loan_amount', 'transaction_amount', 'fraud_amount',
                'account_age_days', 'num_prev_transactions',
                'avg_transaction_value', 'internet_usage_hrs', 'mobile_usage_hrs']

z_scores_max = {}
for col in numeric_cols:
    z = np.abs((df[col] - df[col].mean()) / df[col].std())
    z_scores_max[col] = z.max()

z_df = pd.DataFrame(list(z_scores_max.items()), columns=['Variable', 'Max Z-Score']).sort_values('Max Z-Score', ascending=True)

fig = px.bar(
    z_df,
    x='Max Z-Score', y='Variable',
    orientation='h',
    title='Maximum Absolute Z-Score per Variable',
    color='Max Z-Score',
    color_continuous_scale='Blues',
    template='plotly_white'
)
fig.add_vline(x=3, line_dash='dash', line_color='red',
              annotation_text="Outlier threshold (Z=3)", annotation_position='top')
fig.update_layout(height=480, font_family='Inter, sans-serif', showlegend=False)
fig.show()

Four variables contain notable outliers (Z > 3): fraud_amount reaches over 7 standard deviations above the mean, followed by transaction_amount (~6), loan_amount (~4.8), and mobile_usage_hrs (~3.5). This concentration of extremes in the monetary variables confirms the intuition that fraud is a heavy-tailed phenomenon — most cases are small, but a few are very large.

IQR analysis

Show the code 
def count_outliers_iqr(df, cols, multiplier=1.5):
    counts = {}
    for col in cols:
        Q1 = df[col].quantile(0.25)
        Q3 = df[col].quantile(0.75)
        IQR = Q3 - Q1
        lower = Q1 - multiplier * IQR
        upper = Q3 + multiplier * IQR
        counts[col] = len(df[(df[col] < lower) | (df[col] > upper)])
    return pd.Series(counts).sort_values(ascending=True)

outliers = count_outliers_iqr(df, numeric_cols)
outliers_df = outliers.reset_index()
outliers_df.columns = ['Variable', 'Outlier Count']

fig = px.bar(
    outliers_df,
    x='Outlier Count', y='Variable',
    orientation='h',
    title='Outliers Detected (1.5 × IQR method)',
    color='Outlier Count',
    color_continuous_scale='Blues',
    template='plotly_white'
)
fig.update_layout(height=480, font_family='Inter, sans-serif', showlegend=False)
fig.show()

The IQR method confirms the Z-score findings for fraud_amount, transaction_amount, and loan_amount, and additionally highlights age and personal_income as having notable outliers. These will be important when interpreting segmentation results.

Predictive Modelling

After the exploratory analysis, I trained two classification models: a Decision Tree and a Random Forest. The goal was to see whether the demographic and behavioural features in this dataset could, on their own, predict whether a transaction is fraudulent.

ImportantA note on the modelling results

I want to be transparent: the models I trained delivered modest performance (accuracy around 57–58%). Rather than dismiss this, I treat it as a legitimate finding — the dataset, while clean and balanced, is only 500 rows, and the features available (demographics and transaction metadata) do not carry enough signal to achieve strong classification on their own. The analysis below shows what the models can tell us, and where they fall short.

Key Findings

TipFinding 01 — Age-based fraud patterns are bimodal

The 34–42 age group has fewer fraud incidents but higher losses per case, while the 50–58 group has more incidents but smaller average loss. These represent two distinct fraud profiles that warrant different prevention strategies.

TipFinding 02 — Female customers are affected more frequently

Across nearly every age band, female customers represent a larger share of fraud cases. The pattern is robust in the data, though causation is beyond what this dataset can establish.

TipFinding 03 — ATM and Online channels carry the highest relative loss

ATM transactions showed fraud amounts equal to 81% of their total transaction volume, and Online close behind at 77%. These are the channels where monitoring investment is likely to have the highest return.

TipFinding 04 — Income is the most predictive signal

Across correlation analysis and Random Forest feature importance, income variables (personal and family) consistently emerge as the strongest predictors. Credit score is a close second.

Limitations and Reflection

WarningWhat this project cannot tell us

Dataset size. With only 500 rows, any model is operating in a low-data regime. Classification accuracy around 57% is a direct reflection of this: there simply isn’t enough signal in the available features to separate classes more cleanly. A production system would need tens or hundreds of thousands of transactions to train on.

Feature coverage. The dataset lacks features that are typically the most predictive in real fraud detection: transaction timestamps, merchant categories, geolocation, device fingerprints, and historical behavioural patterns. The demographic features available here are useful for segmentation, but insufficient for accurate prediction.

Causation vs correlation. The gender, age, and education patterns observed are correlations within this sample, not causal claims. Interpreting them as “female customers are more at risk” without additional evidence would be premature.

Model selection. I focused on Decision Tree and Random Forest because they handle mixed-type data well and are interpretable. Gradient boosting (XGBoost, LightGBM) would likely improve the numerical results, but the fundamental constraints of dataset size and feature coverage would remain.

Recommendations

Based on the findings, and explicitly acknowledging the limitations above, I would recommend:

  1. Focus fraud-prevention outreach on the 34–42 and 50–58 age groups — these concentrate the highest monetary losses and highest incident counts respectively.
  2. Prioritise monitoring investment in ATM and Online channels where the fraud-to-transaction ratio is highest.
  3. Extend the dataset before re-training models — adding transaction timestamps, merchant categories, and behavioural history would substantially improve classification performance.
  4. Use this dataset for descriptive insight, not predictive deployment. The EDA findings are actionable; the models are not.

Conclusion

This project was an exercise in applying the full range of statistical techniques learned throughout the module — from descriptive statistics and outlier detection, through correlation analysis and segmentation, to classification modelling. The most valuable lesson I take from it is that a modest model result is still a meaningful outcome when interpreted honestly. The EDA findings are genuinely useful for a business stakeholder; the model is not production-ready, and saying so is more professional than claiming otherwise.

Being rigorous about what the data can and cannot support is, I think, the core skill of a Business Analyst — and this project gave me a clear opportunity to practise it.

### IQR analysis

```{python}
#| label: fig-iqr
#| fig-cap: "Number of outliers detected per variable using the 1.5 × IQR rule."

def count_outliers_iqr(df, cols, multiplier=1.5):
    counts = {}
    for col in cols:
        Q1 = df[col].quantile(0.25)
        Q3 = df[col].quantile(0.75)
        IQR = Q3 - Q1
        lower = Q1 - multiplier * IQR
        upper = Q3 + multiplier * IQR
        counts[col] = len(df[(df[col] < lower) | (df[col] > upper)])
    return pd.Series(counts).sort_values(ascending=True)

outliers = count_outliers_iqr(df, numeric_cols)
outliers_df = outliers.reset_index()
outliers_df.columns = ['Variable', 'Outlier Count']

fig = px.bar(
    outliers_df,
    x='Outlier Count', y='Variable',
    orientation='h',
    title='Outliers Detected (1.5 × IQR method)',
    color='Outlier Count',
    color_continuous_scale='Blues',
    template='plotly_white'
)
fig.update_layout(height=480, font_family='Inter, sans-serif', showlegend=False)
fig.show()
```

The IQR method confirms the Z-score findings for `fraud_amount`, `transaction_amount`, and `loan_amount`, and additionally highlights `age` and `personal_income` as having notable outliers. These will be important when interpreting segmentation results.

## Predictive Modelling

After the exploratory analysis, I trained two classification models: a **Decision Tree** and a **Random Forest**. The goal was to see whether the demographic and behavioural features in this dataset could, on their own, predict whether a transaction is fraudulent.

::: {.callout-important}
## A note on the modelling results
I want to be transparent: the models I trained delivered **modest performance** (accuracy around 57–58%). Rather than dismiss this, I treat it as a legitimate finding — the dataset, while clean and balanced, is only 500 rows, and the features available (demographics and transaction metadata) do not carry enough signal to achieve strong classification on their own. The analysis below shows what the models *can* tell us, and where they fall short.
:::

### Train / Test split

```{python}
#| label: train-test-split

from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import (accuracy_score, precision_score, recall_score,
                             f1_score, confusion_matrix)

y = df['is_fraud']
X = df.drop(columns=['is_fraud', 'transaction_amount', 'fraud_amount',
                     'customer_id', 'gender', 'education', 'marital_status',
                     'Age Group', 'transaction_type', 'device_type'])

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42
)

print(f"Test set:  {len(X_test)} rows")
print(f"\nTrain class balance:")
print(y_train.value_counts(normalize=True).round(3))
```

I dropped `transaction_amount` and `fraud_amount` from the feature set to avoid target leakage — these columns directly encode the fraud outcome and would inflate accuracy artificially.

## Limitations and Reflection

::: {.callout-warning}
## What this project cannot tell us

**Dataset size.** With only 500 rows, any model is operating in a low-data regime. Classification accuracy around 57% is a direct reflection of this: there simply isn't enough signal in the available features to separate classes more cleanly. A production system would need tens or hundreds of thousands of transactions to train on.

**Feature coverage.** The dataset lacks features that are typically the most predictive in real fraud detection: transaction timestamps, merchant categories, geolocation, device fingerprints, and historical behavioural patterns. The demographic features available here are useful for segmentation, but insufficient for accurate prediction.

**Causation vs correlation.** The gender, age, and education patterns observed are correlations within this sample, not causal claims. Interpreting them as "female customers are more at risk" without additional evidence would be premature.

**Model selection.** I focused on Decision Tree and Random Forest because they handle mixed-type data well and are interpretable. Gradient boosting (XGBoost, LightGBM) would likely improve the numerical results, but the fundamental constraints of dataset size and feature coverage would remain.
:::

## Recommendations

Based on the findings, and explicitly acknowledging the limitations above, I would recommend:

1. **Focus fraud-prevention outreach on the 34–42 and 50–58 age groups** — these concentrate the highest monetary losses and highest incident counts respectively.
2. **Prioritise monitoring investment in ATM and Online channels** where the fraud-to-transaction ratio is highest.
3. **Extend the dataset before re-training models** — adding transaction timestamps, merchant categories, and behavioural history would substantially improve classification performance.
4. **Use this dataset for descriptive insight, not predictive deployment.** The EDA findings are actionable; the models are not.
