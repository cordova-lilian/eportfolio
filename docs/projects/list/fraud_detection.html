Overview

Fraud detection is one of the most pressing challenges facing the banking sector today. Financial institutions must balance the operational cost of reviewing transactions against the financial and reputational cost of missing fraudulent ones. This project was developed as part of the Statistical Models and Methods for Business Analytics module, and applies the statistical techniques covered in class to a real-sized transaction dataset.

NoteWhat this project covers
  1. Descriptive statistics and outlier detection using IQR and Z-scores
  2. Correlation analysis between demographic, financial, and behavioural variables
  3. Exploratory segmentation by age, gender, education, and marital status
  4. Statistical validation of segmentation findings with chi-square tests of independence
  5. Classification modelling with five classifiers (a majority-class baseline, Decision Tree, Random Forest, Logistic Regression, and Gradient Boosting), tuned by cross-validation
  6. Honest reflection on model limitations and what the data can — and cannot — tell us

The Dataset

The dataset consists of 500 transactions and 23 original variables including demographic features (age, gender, education, marital status, region), financial features (personal and family income, credit score, loan amount), and behavioural features (transaction amount, device type, mobile and internet usage). The two key target variables are is_fraud (binary indicator) and fraud_amount (total monetary loss).

Outlier Detection

Outliers are particularly relevant in fraud detection, since fraudulent transactions often appear as extreme values in one or more dimensions. I used two complementary approaches: Z-scores and the IQR method.

Z-Score analysis

Show the code 
df_fraud = df[df['is_fraud'] == 1].copy()

IQR analysis

Show the code 
def count_outliers_iqr(df, cols, multiplier=1.5):
    counts = {}
    for col in cols:
        Q1 = df[col].quantile(0.25)
        Q3 = df[col].quantile(0.75)
        IQR = Q3 - Q1
        lower = Q1 - multiplier * IQR
        upper = Q3 + multiplier * IQR
        counts[col] = len(df[(df[col] < lower) | (df[col] > upper)])
    return pd.Series(counts).sort_values(ascending=True)

outliers = count_outliers_iqr(df, numeric_cols)
outliers_df = outliers.reset_index()
outliers_df.columns = ['Variable', 'Outlier Count']

fig = px.bar(
    outliers_df,
    x='Outlier Count', y='Variable',
    orientation='h',
    title='Outliers Detected (1.5 × IQR method)',
    color='Outlier Count',
    color_continuous_scale='Blues',
    template='plotly_white'
)
fig.update_layout(height=480, font_family='Inter, sans-serif', showlegend=False)
fig.show()

The IQR method confirms the Z-score findings for fraud_amount, transaction_amount, and loan_amount, and additionally highlights age and personal_income as having notable outliers. These will be important when interpreting segmentation results.

Which of these patterns are statistically real?

A bar chart showing a gap between groups isn’t evidence on its own that the gap is real, especially with 500 rows, it could easily be sampling noise. A chi-square test of independence checks this directly: for each variable, it compares the actual counts of fraud vs. not-fraud within each group, against the counts you’d expect if the variable had no relationship to fraud at all, using the full dataset, not just the fraud cases shown in the charts above, so each group’s size is properly accounted for.

Show the code 
from scipy.stats import chi2_contingency

chi_results = []
for var in ['gender', 'Age Group', 'education', 'marital_status', 'transaction_type', 'device_type']:
    table = pd.crosstab(df[var], df['is_fraud'])
    chi2, p, dof, expected = chi2_contingency(table)
    chi_results.append({
        'Variable': var,
        'chi2': round(chi2, 3),
        'p_value': round(p, 4),
        'min_expected_count': round(expected.min(), 2),
        'Significant (p < 0.05)': 'Yes' if p < 0.05 else 'No'
    })

chi_df = pd.DataFrame(chi_results)
chi_df

Gender is genuinely associated with fraud (p = 0.0069) — the gap shown in the gender chart above is real, not noise. Age group is also significant (p = 0.027), but several of its bins have expected counts below 5, the usual rule-of-thumb minimum for trusting the test, so that result is suggestive rather than solid. Education, marital status, transaction type, and device type all come back not significant (p > 0.2 in every case) — their charts may look like they show a pattern, but that pattern is statistically indistinguishable from random variation in a sample this size. Any finding below is limited to what this test actually supports.

Predictive Modelling

After the exploratory analysis, I trained and compared five classifiers: a majority-class Dummy baseline, a Decision Tree, a Random Forest, Logistic Regression, and Gradient Boosting. The goal was twofold — see whether the demographic and behavioural features in this dataset could predict whether a transaction is fraudulent, and check whether a simple, interpretable model could hold its own against more complex ones rather than assuming more complexity is automatically better.

ImportantA note on the modelling results

Two things changed since an earlier version of this analysis, and I want to be transparent about both. First, I found and fixed a data leak: transaction_id, a raw case identifier, was still in the feature set, and a permutation-importance check showed the model was drawing spurious signal from it, a row ID has no legitimate relationship to fraud. Second, I moved from a single train/test split with hyperparameters chosen by watching test-set accuracy, to 5-fold cross-validation on the training data only, with the test set touched exactly once, at the very end, to produce the numbers reported below. With both fixes in place, the best model (Random Forest) reaches 63.3% accuracy and 64.9% recall, better than what an earlier, leakier version of this analysis reported, though still modest: the dataset is only 500 rows, and the available features (demographics and transaction metadata) don’t carry enough signal for strong classification on their own. The analysis below shows what the models can tell us, and where they still fall short.

I dropped transaction_amount and fraud_amount to avoid target leakage — these columns directly encode the fraud outcome and would inflate accuracy artificially. I also dropped transaction_id: it’s just a row identifier and should carry no real predictive signal, but an earlier version of this analysis left it in, and the model was able to exploit it anyway. Choosing hyperparameters without peeking at the test set

max_depth (Decision Tree) and max_features (Random Forest) are tuned using 5-fold cross-validation on the training set only. Picking a hyperparameter by watching how it scores on the test set quietly lets test-set information leak into the modelling decisions, so the final “test” score stops being an honest estimate of performance on unseen data.

Show the cross-validation sweep for max_depth and max_features 
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
scoring = ['accuracy', 'precision', 'recall', 'f1']

depth_results = []
for depth in range(2, 21):
    res = cross_validate(DecisionTreeClassifier(max_depth=depth, random_state=42),
                          X_train, y_train, cv=cv, scoring=scoring)
    depth_results.append({'max_depth': depth, 'cv_f1': res['test_f1'].mean()})
depth_df = pd.DataFrame(depth_results)
best_depth = int(depth_df.loc[depth_df['cv_f1'].idxmax(), 'max_depth'])

rf_results = []
for max_feat in [3, 5, 'sqrt', 'log2', None]:
    res = cross_validate(RandomForestClassifier(n_estimators=200, max_features=max_feat, random_state=42),
                          X_train, y_train, cv=cv, scoring=scoring)
    rf_results.append({'max_features': str(max_feat), 'cv_recall': res['test_recall'].mean()})
rf_df = pd.DataFrame(rf_results)
best_rf_feat = rf_df.loc[rf_df['cv_recall'].idxmax(), 'max_features']
best_rf_feat = None if best_rf_feat == 'None' else best_rf_feat

print(f"Decision Tree — best max_depth by 5-fold CV F1: {best_depth}")
print(f"Random Forest — best max_features by 5-fold CV recall: {best_rf_feat}")
Decision Tree — best max_depth by 5-fold CV F1: 4
Random Forest — best max_features by 5-fold CV recall: None

The shallowest well-performing depth (4) wins for the Decision Tree. That’s a shallow tree for 350 training rows, and it turns out to be unstable — its held-out recall below comes out much higher than the cross-validated estimate suggested, at the cost of weak precision, a sign the tree’s exact split points shift a lot depending on which rows land in which fold.

Model comparison

Show the code 
logreg_pipe = Pipeline([
    ('scaler', StandardScaler()),
    ('clf', LogisticRegression(max_iter=2000, random_state=42))

final_models = {
    'Dummy (baseline)': DummyClassifier(strategy='most_frequent'),
    f'Decision Tree (depth={best_depth})': DecisionTreeClassifier(max_depth=best_depth, random_state=42),

Random Forest gives the best overall balance (63.3% accuracy, 64.9% recall). Gradient Boosting scores slightly lower on accuracy (59.3%) but has the best recall of all five (68.9%), worth naming explicitly since recall is the metric that matters most here — missing a real fraud case is more costly than a false alarm. Logistic Regression, the simplest and most interpretable model of the five, comes close to Random Forest (61.3% accuracy, 63.5% recall), which suggests most of the signal in this data is close to linear rather than requiring an ensemble to capture it. All five clear the 50.7% majority-class baseline, though not by a wide margin, consistent with a genuinely hard problem given the features available.

Key Findings

TipFinding 01 — Age-based fraud patterns are bimodal, and statistically real (with a caveat)

The 34–42 age group has fewer fraud incidents but higher losses per case, while the 50–58 group has more incidents but smaller average loss. A chi-square test confirms age group is associated with fraud incidence (p = 0.027), though several age bins have low expected counts, so this should be read as suggestive rather than conclusive. These represent two distinct fraud profiles that warrant different prevention strategies.

TipFinding 02 — Female customers are affected more frequently, and this is the strongest validated pattern in the data

Across nearly every age band, female customers represent a larger share of fraud cases. A chi-square test confirms this is a genuine association (p = 0.0069), the clearest statistically-supported demographic pattern in the whole analysis. Causation is still beyond what this dataset can establish.

TipFinding 03 — ATM and Online channels carry the highest relative loss

ATM transactions showed fraud amounts equal to 81% of their total transaction volume, and Online close behind at 77%. These are the channels where monitoring investment is likely to have the highest return. This is a severity measure, not an incidence one — a chi-square test found transaction type is not significantly associated with whether a transaction is fraud in the first place (p > 0.2), so it doesn’t contradict this finding, but it does mean transaction type isn’t a useful flag for predicting fraud up front.

TipFinding 04 — Financial and behavioural variables are the most predictive signal, not just income

Random Forest feature importance points to personal income, age, and family income at the top, but account age, average transaction value, credit score, and usage patterns all rank close behind — a broader financial-and-behavioural story rather than income alone. Encouragingly, this lines up with the chi-square results: none of the variables the significance test ruled out (education, marital status, transaction type, device type) rank highly here either.

TipFinding 05 — Education, marital status, and device type are not statistically validated

Their charts in the segmentation section show visible differences between groups, but a chi-square test found none of them significantly associated with fraud incidence (p > 0.2 in every case). Shown for completeness in the exploratory section, but they shouldn’t be treated as real drivers of fraud risk without a larger dataset.

Limitations and Reflection

WarningWhat this project cannot tell us

Dataset size. With only 500 rows (350 for training), any model is operating in a low-data regime. The best result, 63.3% accuracy from Random Forest, is a direct reflection of this: there simply isn’t enough signal in the available features to separate classes more cleanly. A production system would need tens or hundreds of thousands of transactions to train on.

Feature coverage. The dataset lacks features that are typically the most predictive in real fraud detection: transaction timestamps, merchant categories, geolocation, device fingerprints, and historical behavioural patterns. The demographic features available here are useful for segmentation, but insufficient for accurate prediction.

Causation vs correlation. Even the statistically validated patterns (gender, and age group with its caveat) are correlations within this sample, not causal claims. Interpreting the gender finding as “women are more at risk of fraud” in general, rather than “more at risk within this 500-row sample,” would be premature.

Model selection. The comparison above already includes Gradient Boosting alongside Decision Tree and Random Forest, and it did not meaningfully outperform them — it traded a few points of accuracy for better recall, rather than lifting the ceiling. That’s a useful finding in itself: the constraint here is dataset size and feature coverage, not the choice of algorithm, since a fundamentally different tree-based method landed in the same range as the simpler models.

Recommendations

Based on the findings, and explicitly acknowledging the limitations above, I would recommend:

  1. Focus fraud-prevention outreach on the 34–42 and 50–58 age groups — these concentrate the highest monetary losses and highest incident counts respectively.
  2. Prioritise monitoring investment in ATM and Online channels where the fraud-to-transaction ratio is highest.
  3. Extend the dataset before re-training models — adding transaction timestamps, merchant categories, and behavioural history would substantially improve classification performance.
  4. Use this dataset for descriptive insight, not predictive deployment. The EDA findings are actionable; the models are not.

Conclusion

This project was an exercise in applying the full range of statistical techniques learned throughout the module — from descriptive statistics and outlier detection, through correlation analysis and segmentation, to classification modelling. The most valuable lesson I take from it is that a modest model result is still a meaningful outcome when interpreted honestly. The EDA findings are genuinely useful for a business stakeholder; the model is not production-ready, and saying so is more professional than claiming otherwise.

Being rigorous about what the data can and cannot support is, I think, the core skill of a Business Analyst — and this project gave me a clear opportunity to practise it.

## Outlier Detection

Outliers are particularly relevant in fraud detection, since fraudulent transactions often appear as extreme values in one or more dimensions. I used two complementary approaches: Z-scores and the IQR method.

### Z-Score analysis

```{python}

df_fraud = df[df['is_fraud'] == 1].copy()
```

### IQR analysis

```{python}
#| label: fig-iqr
#| fig-cap: "Number of outliers detected per variable using the 1.5 × IQR rule."

def count_outliers_iqr(df, cols, multiplier=1.5):
    counts = {}
    for col in cols:
        Q1 = df[col].quantile(0.25)
        Q3 = df[col].quantile(0.75)
        IQR = Q3 - Q1
        lower = Q1 - multiplier * IQR
        upper = Q3 + multiplier * IQR
        counts[col] = len(df[(df[col] < lower) | (df[col] > upper)])
    return pd.Series(counts).sort_values(ascending=True)

outliers = count_outliers_iqr(df, numeric_cols)
outliers_df = outliers.reset_index()
outliers_df.columns = ['Variable', 'Outlier Count']

fig = px.bar(
    outliers_df,
    x='Outlier Count', y='Variable',
    orientation='h',
    title='Outliers Detected (1.5 × IQR method)',
    color='Outlier Count',
    color_continuous_scale='Blues',
    template='plotly_white'
)
fig.update_layout(height=480, font_family='Inter, sans-serif', showlegend=False)
fig.show()
```

The IQR method confirms the Z-score findings for `fraud_amount`, `transaction_amount`, and `loan_amount`, and additionally highlights `age` and `personal_income` as having notable outliers. These will be important when interpreting segmentation results.

### Which of these patterns are statistically real?

A bar chart showing a gap between groups isn't evidence on its own that the gap is real, especially with 500 rows, it could easily be sampling noise. A chi-square test of independence checks this directly: for each variable, it compares the actual counts of fraud vs. not-fraud within each group, against the counts you'd expect if the variable had no relationship to fraud at all, using the **full dataset**, not just the fraud cases shown in the charts above, so each group's size is properly accounted for.

```{python}
#| label: tbl-chisquare
#| tbl-cap: "Chi-square test of independence: is fraud incidence associated with each variable?"

from scipy.stats import chi2_contingency

chi_results = []
for var in ['gender', 'Age Group', 'education', 'marital_status', 'transaction_type', 'device_type']:
    table = pd.crosstab(df[var], df['is_fraud'])
    chi2, p, dof, expected = chi2_contingency(table)
    chi_results.append({
        'Variable': var,
        'chi2': round(chi2, 3),
        'p_value': round(p, 4),
        'min_expected_count': round(expected.min(), 2),
        'Significant (p < 0.05)': 'Yes' if p < 0.05 else 'No'
    })

chi_df = pd.DataFrame(chi_results)
chi_df
```

**Gender** is genuinely associated with fraud (p = 0.0069) — the gap shown in the gender chart above is real, not noise. **Age group** is also significant (p = 0.027), but several of its bins have expected counts below 5, the usual rule-of-thumb minimum for trusting the test, so that result is suggestive rather than solid. **Education, marital status, transaction type, and device type all come back not significant** (p > 0.2 in every case) — their charts may look like they show a pattern, but that pattern is statistically indistinguishable from random variation in a sample this size. Any finding below is limited to what this test actually supports.

## Predictive Modelling

After the exploratory analysis, I trained and compared five classifiers: a majority-class **Dummy** baseline, a **Decision Tree**, a **Random Forest**, **Logistic Regression**, and **Gradient Boosting**. The goal was twofold — see whether the demographic and behavioural features in this dataset could predict whether a transaction is fraudulent, and check whether a simple, interpretable model could hold its own against more complex ones rather than assuming more complexity is automatically better.

::: {.callout-important}
## A note on the modelling results
Two things changed since an earlier version of this analysis, and I want to be transparent about both. First, I found and fixed a data leak: `transaction_id`, a raw case identifier, was still in the feature set, and a permutation-importance check showed the model was drawing spurious signal from it, a row ID has no legitimate relationship to fraud. Second, I moved from a single train/test split with hyperparameters chosen by watching test-set accuracy, to 5-fold cross-validation on the training data only, with the test set touched exactly once, at the very end, to produce the numbers reported below. With both fixes in place, the best model (Random Forest) reaches **63.3% accuracy and 64.9% recall**, better than what an earlier, leakier version of this analysis reported, though still modest: the dataset is only 500 rows, and the available features (demographics and transaction metadata) don't carry enough signal for strong classification on their own. The analysis below shows what the models *can* tell us, and where they still fall short.
:::

### Train / Test split

```{python}
#| label: train-test-split

from sklearn.model_selection import train_test_split, StratifiedKFold, cross_validate
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier
from sklearn.tree import DecisionTreeClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.dummy import DummyClassifier
from sklearn.metrics import (accuracy_score, precision_score, recall_score,
                             f1_score, confusion_matrix)

y = df['is_fraud']
X = df.drop(columns=['is_fraud', 'transaction_amount', 'fraud_amount',
                     'customer_id', 'transaction_id', 'gender', 'education',
                     'marital_status', 'Age Group', 'transaction_type', 'device_type'])

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42, stratify=y
)

print(f"Train set: {len(X_train)} rows")
print(f"Test set:  {len(X_test)} rows")
print(f"\nTrain class balance:")
print(y_train.value_counts(normalize=True).round(3))
```

I dropped `transaction_amount` and `fraud_amount` to avoid target leakage — these columns directly encode the fraud outcome and would inflate accuracy artificially. I also dropped `transaction_id`: it's just a row identifier and should carry no real predictive signal, but an earlier version of this analysis left it in, and the model was able to exploit it anyway. The split is now stratified on `is_fraud`, so the train and test sets keep the same fraud/non-fraud ratio as the full dataset.

### Choosing hyperparameters without peeking at the test set

`max_depth` (Decision Tree) and `max_features` (Random Forest) are tuned using 5-fold cross-validation **on the training set only**. Picking a hyperparameter by watching how it scores on the test set quietly lets test-set information leak into the modelling decisions, so the final "test" score stops being an honest estimate of performance on unseen data.

```{python}
#| label: cv-tuning
#| code-summary: "Show the cross-validation sweep for max_depth and max_features"

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
scoring = ['accuracy', 'precision', 'recall', 'f1']

depth_results = []
for depth in range(2, 21):
    res = cross_validate(DecisionTreeClassifier(max_depth=depth, random_state=42),
                          X_train, y_train, cv=cv, scoring=scoring)
    depth_results.append({'max_depth': depth, 'cv_f1': res['test_f1'].mean()})
depth_df = pd.DataFrame(depth_results)
best_depth = int(depth_df.loc[depth_df['cv_f1'].idxmax(), 'max_depth'])

rf_results = []
for max_feat in [3, 5, 'sqrt', 'log2', None]:
    res = cross_validate(RandomForestClassifier(n_estimators=200, max_features=max_feat, random_state=42),
                          X_train, y_train, cv=cv, scoring=scoring)
    rf_results.append({'max_features': str(max_feat), 'cv_recall': res['test_recall'].mean()})
rf_df = pd.DataFrame(rf_results)
best_rf_feat = rf_df.loc[rf_df['cv_recall'].idxmax(), 'max_features']
best_rf_feat = None if best_rf_feat == 'None' else best_rf_feat

print(f"Decision Tree — best max_depth by 5-fold CV F1: {best_depth}")
print(f"Random Forest — best max_features by 5-fold CV recall: {best_rf_feat}")
```

The shallowest well-performing depth (4) wins for the Decision Tree. That's a shallow tree for 350 training rows, and it turns out to be unstable — its held-out recall below comes out much higher than the cross-validated estimate suggested, at the cost of weak precision, a sign the tree's exact split points shift a lot depending on which rows land in which fold.

```{python}
fig.update_traces(textposition='outside', textfont_size=9)
```

Random Forest gives the best overall balance (63.3% accuracy, 64.9% recall). Gradient Boosting scores slightly lower on accuracy (59.3%) but has the best recall of all five (68.9%), worth naming explicitly since recall is the metric that matters most here — missing a real fraud case is more costly than a false alarm. Logistic Regression, the simplest and most interpretable model of the five, comes close to Random Forest (61.3% accuracy, 63.5% recall), which suggests most of the signal in this data is close to linear rather than requiring an ensemble to capture it. ## Key Findings

::: {.callout-tip icon=false}
## Finding 01 — Age-based fraud patterns are bimodal, and statistically real (with a caveat)
The 34–42 age group has **fewer fraud incidents but higher losses per case**, while the 50–58 group has **more incidents but smaller average loss**. A chi-square test confirms age group is associated with fraud incidence (p = 0.027), though several age bins have low expected counts, so this should be read as suggestive rather than conclusive. These represent two distinct fraud profiles that warrant different prevention strategies.
:::

::: {.callout-tip icon=false}
## Finding 02 — Female customers are affected more frequently, and this is the strongest validated pattern in the data
Across nearly every age band, female customers represent a larger share of fraud cases. A chi-square test confirms this is a genuine association (p = 0.0069), the clearest statistically-supported demographic pattern in the whole analysis. Causation is still beyond what this dataset can establish.
:::

::: {.callout-tip icon=false}
## Finding 03 — ATM and Online channels carry the highest relative loss
ATM transactions showed fraud amounts equal to 81% of their total transaction volume, and Online close behind at 77%. These are the channels where monitoring investment is likely to have the highest return. This is a severity measure, not an incidence one — a chi-square test found transaction type is *not* significantly associated with whether a transaction is fraud in the first place (p > 0.2), so it doesn't contradict this finding, but it does mean transaction type isn't a useful flag for predicting fraud up front.
:::

::: {.callout-tip icon=false}
## Finding 04 — Financial and behavioural variables are the most predictive signal, not just income
Random Forest feature importance points to personal income, age, and family income at the top, but account age, average transaction value, credit score, and usage patterns all rank close behind — a broader financial-and-behavioural story rather than income alone. Encouragingly, this lines up with the chi-square results: none of the variables the significance test ruled out (education, marital status, transaction type, device type) rank highly here either.
:::

::: {.callout-tip icon=false}
## Finding 05 — Education, marital status, and device type are not statistically validated
Their charts in the segmentation section show visible differences between groups, but a chi-square test found none of them significantly associated with fraud incidence (p > 0.2 in every case). Shown for completeness in the exploratory section, but they shouldn't be treated as real drivers of fraud risk without a larger dataset.
:::

## Limitations and Reflection

::: {.callout-warning}
## What this project cannot tell us

**Dataset size.** With only 500 rows (350 for training), any model is operating in a low-data regime. The best result, 63.3% accuracy from Random Forest, is a direct reflection of this: there simply isn't enough signal in the available features to separate classes more cleanly. A production system would need tens or hundreds of thousands of transactions to train on.

**Feature coverage.** The dataset lacks features that are typically the most predictive in real fraud detection: transaction timestamps, merchant categories, geolocation, device fingerprints, and historical behavioural patterns. The demographic features available here are useful for segmentation, but insufficient for accurate prediction.

**Causation vs correlation.** Even the statistically validated patterns (gender, and age group with its caveat) are correlations within this sample, not causal claims. Interpreting the gender finding as "women are more at risk of fraud" in general, rather than "more at risk within this 500-row sample," would be premature.

**Model selection.** The comparison above already includes Gradient Boosting alongside Decision Tree and Random Forest, and it did not meaningfully outperform them — it traded a few points of accuracy for better recall, rather than lifting the ceiling. That's a useful finding in itself: the constraint here is dataset size and feature coverage, not the choice of algorithm, since a fundamentally different tree-based method landed in the same range as the simpler models.
:::

## Recommendations

Based on the findings, and explicitly acknowledging the limitations above, I would recommend:

1. **Focus fraud-prevention outreach on the 34–42 and 50–58 age groups** — these concentrate the highest monetary losses and highest incident counts respectively.
2. **Prioritise monitoring investment in ATM and Online channels** where the fraud-to-transaction ratio is highest.
3. **Extend the dataset before re-training models** — adding transaction timestamps, merchant categories, and behavioural history would substantially improve classification performance.
4. **Use this dataset for descriptive insight, not predictive deployment.** The EDA findings are actionable; the models are not.
