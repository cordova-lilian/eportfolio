Overview

Financial firms process thousands of news items daily to inform trading, risk, and portfolio decisions. Manually classifying sentiment at scale is infeasible. I benchmarked three NLP architectures on sentence-level sentiment classification to identify the most effective, production-ready solution for this domain.

NoteThe question

Which architecture delivers the best sentiment classification on financial text: general-purpose BERT, domain-pretrained FinBERT, or a much larger zero-shot LLaMA 3.2?

The Approach

Dataset. Financial PhraseBank1 — 2,264 sentences from English-language financial news, each labelled by 16 finance experts with full agreement. Stratified 80/20 split to preserve class proportions.

Three models tested. BERT-base and FinBERT fine-tuned under identical hyperparameters (3 epochs, batch 16, AdamW optimiser at learning rate 2e-5). LLaMA 3.2 (3B parameters) run zero-shot via Ollama at temperature 0 — no fine-tuning.

Evaluation metrics. Accuracy, precision, recall, weighted F1, and confusion matrices. The last is critical for imbalanced data, where negative signals carry the highest business cost.

The cleaning step is intentionally minimal — transformer tokenisers handle most normalisation internally, so heavy preprocessing can actually hurt performance.

    # Collapse whitespace only — let the tokeniser do the rest

What I Found

TipFinding 01 — Domain pre-training beats raw scale

FinBERT (110M parameters, pre-trained on Reuters financial news) outperformed both general BERT and the much larger LLaMA 3.2 (3B parameters). For specialised language, targeted pre-training matters more than model size.

TipFinding 02 — Zero-shot is surprisingly viable

LLaMA 3.2 reached 86.8% with zero labelled examples. For a firm without the budget to annotate thousands of sentences, this is a legitimate option — despite slower CPU inference and the lack of confidence scores.

TipFinding 03 — The minority class is the bottleneck

All three models showed the highest error on the negative class (303 of 2,264 rows). Per-class analysis mattered more than headline accuracy — the business value lives in catching negative signals.

TipFinding 04 — Recommendation

Deploy FinBERT for real-time sentiment on trading desks. Keep LLaMA 3.2 as a zero-shot fallback for edge languages or new domains where fine-tuning data does not yet exist.

Limitations & Next Steps

  • Class imbalance. Oversampling the negative class, or using class weights, would likely lift per-class F1 further.
  • Inference cost. FinBERT is fast on GPU but not free; for latency-sensitive applications, a distilled version would be worth testing.
  • Domain drift. Financial language evolves (new instruments, new terminology). Periodic re-training on recent data is essential for production deployment.
  • Multilingual extension. The PhraseBank is English-only. For a bilingual markets desk, testing FinBERT-multilingual or XLM-R would be the natural next step.

## Overview

Financial firms process thousands of news items daily to inform trading, risk, and portfolio decisions. Manually classifying sentiment at scale is infeasible. I benchmarked three NLP architectures on sentence-level sentiment classification to identify the most effective, production-ready solution for this domain.

::: {.callout-note}
## The question
Which architecture delivers the best sentiment classification on financial text: general-purpose BERT, domain-pretrained FinBERT, or a much larger zero-shot LLaMA 3.2?

## The Approach

**Dataset.** Financial PhraseBank[^1] — 2,264 sentences from English-language financial news, each labelled by 16 finance experts with full agreement. Stratified 80/20 split to preserve class proportions.

[^1]: Malo, P., Sinha, A., Korhonen, P., Wallenius, J., & Takala, P. (2014). *Good debt or bad debt: Detecting semantic orientations in economic texts*. Journal of the Association for Information Science and Technology.

**Three models tested.** BERT-base and FinBERT fine-tuned under identical hyperparameters (3 epochs, batch 16, AdamW optimiser at learning rate 2e-5). LLaMA 3.2 (3B parameters) run zero-shot via Ollama at temperature 0 — no fine-tuning.

**Evaluation metrics.** Accuracy, precision, recall, weighted F1, and confusion matrices. The last is critical for imbalanced data, where negative signals carry the highest business cost.

## Model 3 — LLaMA 3.2 Zero-Shot

LLaMA 3.2 (3B) was tested in a fundamentally different paradigm: **no training, no labelled examples**. The model was prompted directly via Ollama to classify each sentence.

```{python}
#| label: llama
#| eval: false

import requests

PROMPT_TEMPLATE = """Classify the sentiment of this financial news sentence as exactly one of:
negative, neutral, or positive.

Sentence: "{sentence}"

Sentiment:"""

def llama_classify(sentence):
    response = requests.post('http://localhost:11434/api/generate', json={
        'model': 'llama3.2:3b',
        'prompt': PROMPT_TEMPLATE.format(sentence=sentence),
        'temperature': 0,
        'stream': False
    })
    return response.json()['response'].strip().lower()

# Run on all 453 test sentences
llama_predictions = [llama_classify(s) for s in test_texts]
```

## What I Found

::: {.callout-tip icon=false}
## Finding 01 — Domain pre-training beats raw scale
FinBERT (110M parameters, pre-trained on Reuters financial news) outperformed both general BERT and the much larger LLaMA 3.2 (3B parameters). **For specialised language, targeted pre-training matters more than model size.**
:::

::: {.callout-tip icon=false}
## Finding 02 — Zero-shot is surprisingly viable
LLaMA 3.2 reached 86.8% with zero labelled examples. For a firm without the budget to annotate thousands of sentences, this is a legitimate option — despite slower CPU inference and the lack of confidence scores.
:::

::: {.callout-tip icon=false}
## Finding 03 — The minority class is the bottleneck
All three models showed the highest error on the negative class (303 of 2,264 rows). **Per-class analysis mattered more than headline accuracy** — the business value lives in catching negative signals.
:::

::: {.callout-tip icon=false}
## Finding 04 — Recommendation
Deploy **FinBERT** for real-time sentiment on trading desks. Keep **LLaMA 3.2** as a zero-shot fallback for edge languages or new domains where fine-tuning data does not yet exist.
:::

## Limitations & Next Steps

- **Class imbalance.** Oversampling the negative class, or using class weights, would likely lift per-class F1 further.
- **Inference cost.** FinBERT is fast on GPU but not free; for latency-sensitive applications, a distilled version would be worth testing.
- **Domain drift.** Financial language evolves (new instruments, new terminology). Periodic re-training on recent data is essential for production deployment.
- **Multilingual extension.** The PhraseBank is English-only. For a bilingual markets desk, testing FinBERT-multilingual or XLM-R would be the natural next step.
